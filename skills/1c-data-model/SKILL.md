\# 1C Physical Data Model



Используй этот skill как установленную модель физической структуры 1С.



Не исследуй заново следующие вещи, если пользователь явно не сообщает,

что модель изменилась.



Основные инварианты:



1\. DEC\_ID — числовой идентификатор объекта.

2\. HEX\_ID — только HEX-представление DEC\_ID.

3\. parent\_dec\_id — структурный родитель.

4\. target\_dec\_id — объект, являющийся целью ссылочного поля.

5\. parent\_dec\_id и target\_dec\_id не взаимозаменяемы.

6\. parent\_dec\_id IS NULL → основной объект.

7\. parent\_dec\_id IS NOT NULL → табличная часть / дочерний структурный узел.

8\. \_TYPE = 0x08 → Ref.

9\. \_TYPE и \_RTRef имеют разные функции.

10\. \_RTRef используется для определения конкретного типа/объекта ссылки.

11\. \_RRRef идентифицирует конкретную запись объекта ссылки.

12\. Составной тип анализируется как группа связанных физических полей:

&#x20;   \_TYPE + \_RTRef + \_RRRef + соответствующие primitive-поля.

13\. Поля табличной части принадлежат узлу табличной части, а не напрямую

&#x20;   основному объекту.

14\. Для восстановления структуры сначала использовать формальные

&#x20;   идентификаторы и связи метаданных, а не имена и эвристики.



Перед поиском по проекту сначала сопоставляй задачу с этой моделью.

Не выполняй повторное исследование уже установленных инвариантов.
