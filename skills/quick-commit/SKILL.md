# Быстрый коммит изменений (git)

Используй этот skill, когда пользователь просит закоммитить изменения, «сохранить работу», «скинь в гит», «закоммить и запушить», или когда нужно быстро зафиксировать текущее состояние репозитория.

## Быстрый путь: `git p "сообщение"`

Глобальный алиас (проверен, `git config --global`):

```
alias.p = !f() { git add -A && git commit -m "$1" && git push; }; f
```

Одна команда = `git add -A` + `git commit -m "сообщение"` + `git push`.

```bash
git p "архивация 26-10-26"
```

## Когда НЕ использовать `p`

`git add -A` добавляет ВСЁ. Если в `git status` есть чужие/нежелательные изменения — коммить выборочно:

```bash
git add path/to/file.py
git commit -m "сообщение"
git push
```

Никогда не коммить чужие изменения, не согласованные с пользователем.

## Безопасность перед коммитом

Перед `git add -A` быстро просканируй, что попадает в коммит:

- **Секреты**: API-ключи (`sk-...`, `Bearer`), пароли, connection-strings (`Password=...`), сессионные куки. Если нашёл — замаскируй (`__REDACTED__`) или исключи из коммита.
- **Мусор**: `__pycache__/`, `*.pyc`, `~$*` (временные файлы Office), дампы данных, `.env`.
- **Вложенные репозитории**: если внутри репо есть свой `.git` (например, `qwenCLI/` внутри `QWEN_LOC`), `git add -A` добавит его как gitlink — проверяй `git status`.

## Стиль сообщений

Короткие, по-русски, часто с датой (примеры из истории):

- `архивация 23,09,26`
- `архивация 23,09,26 — очистка индекса`
- `Перенес настройки .qwen в локальную папку проекта`
- `DashBord: модульный сайт (core/pages/web) + страница «Структура»...`

Формат: `что сделано` или `что сделано — уточнение`. Без "fix", "update" и прочего англо-шума.

## Типовой сценарий «сохранить всё»

1. `git status` — что изменилось, нет ли чужого/мусора
2. Быстрый скан на секреты (см. выше)
3. `git p "сообщение"` — add + commit + push одной командой
4. `git status` — подтвердить, что дерево чистое

## Если push не прошёл

| Ошибка | Решение |
|---|---|
| `could not read Username` | Нет креденшелов — `git credential fill` или добавить в Credential Manager |
| `rejected (fetch first)` | `git pull --rebase` и повторить push |
| `no upstream branch` | `git push -u origin main` |

Никогда не force-push без явного разрешения пользователя.
