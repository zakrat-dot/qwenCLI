## Обычная ссылка vs Составная ссылка

| Тип | Физические поля | Когда нужен _RTRef |
|-----|----------------|-------------------|
| **Обычная ссылка** `_FldXXXXX_RRef` | Одно поле | Нет — тип известен из метаданных |
| **Составная ссылка** `_FldXXXXX_TYPE` + `_FldXXXXX_RTRef` + `_FldXXXXX_RRRef` | Группа полей | Да — тип определяется динамически |

## Физические колонки — полное правило формирования

Составной тип раскладывается на группу колонок в зависимости от разрешённых типов:

| Разрешённые типы | Физические колонки |
|-----------------|-------------------|
| Строка \| Число | `_TYPE`, `_S`, `_N` |
| Булево \| Дата | `_TYPE`, `_L`, `_T` |
| Ссылка A \| Ссылка B | `_TYPE`, `_RTRef`, `_RRRef` |
| Булево \| Ссылка A | `_TYPE`, `_L`, `_RTRef`, `_RRRef` |
| Число \| Строка \| Дата \| Ссылка A \| Ссылка B | `_TYPE`, `_N`, `_S`, `_T`, `_RTRef`, `_RRRef` |

### Коды _TYPE для примитивов

| _TYPE | Тип | Колонка значения |
|-------|-----|-----------------|
| 0x02 | Булево | `_L` |
| 0x03 | Число | `_N` |
| 0x04 | Дата | `_T` |
| 0x05 | Строка | `_S` |
| 0x06 | BLOB | `_B` |
| 0x08 | Ссылка на объект | `_RTRef` + `_RRRef` |
| 0x00 | Null / неопределено | — |

## Алгоритм обратного восстановления (двустороннее сопоставление)

### Прямое направление: метаданные → физика

```
Реквизит 1C
  ↓
Типы: Строка, Дата, СправочникСсылка.Номенклатура
  ↓
Ожидаемая группа колонок:
  _Fld<N>_TYPE
  _Fld<N>_S       ← Строка
  _Fld<N>_T       ← Дата
  _Fld<N>_RTRef   ← тип ссылки
  _Fld<N>_RRRef   ← ID записи
  ↓
Сопоставление с реальной SQL-таблицей по Fld<N>
```

### Обратное направление: физика → метаданные

```
SQL-поле _Fld<N>_TYPE
  ↓
  _TYPE = 0x02 → Булево, значение в _L
  _TYPE = 0x03 → Число, значение в _N
  _TYPE = 0x04 → Дата, значение в _T
  _TYPE = 0x05 → Строка, значение в _S
  _TYPE = 0x06 → BLOB, значение в _B
  _TYPE = 0x08 → Ссылка
  _TYPE = 0x00 → Null / неопределено
                    ↓ (если ссылка)
              _RTRef → тип объекта
              _RRRef → ID записи
                    ↓
              объект 1C
```

## Почему это важно для дашборда

При построении JOIN для полей с `_TYPE`/`_RTRef`/`_RRRef`:
- Сначала `_TYPE` → это ссылка?
- Потом `_RTRef` → какой объект? (через `meta_schema.nodes`)
- Потом `_RRRef` → какая запись? (JOIN по `_IDRRef`)
- `target_dec_id` для составного поля нельзя определить только по имени — нужно разрешить `_RTRef`
- Группа колонок определяется **множеством разрешённых типов** из метаданных
