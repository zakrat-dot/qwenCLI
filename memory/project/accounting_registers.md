## Ключевые колонки _AccRg1112

| Колонка | Назначение |
|---|---|
| `_Period` | Дата/время проводки (datetime2, со сдвигом +2000) |
| `_Active` | Активная проводка = `1` (НЕ `_Posted` — такой колонки нет!) |
| `_Fld1116` | Сумма в рублях (НЕ `_Fld1117` — это валютная сумма) |
| `_Fld1113RRef` | Ссылка на организацию → `_Reference150._IDRRef` |
| `_Fld1122` | Содержание проводки |
| `_AccountDtRRef` | Дебет счёт → `_Acc36._IDRRef` |
| `_AccountCtRRef` | Кредит счёт → `_Acc36._IDRRef` |

## Смещение дат +2000 лет

```python
DATE_SHIFT = 2000

def shift_date(date_str):   # '2026-09-29' → '4026-09-29'
    d = datetime.strptime(date_str, '%Y-%m-%d')
    return d.replace(year=d.year + DATE_SHIFT)

def unshift_date(dt):       # 4026-09-29 → '29.09.2026'
    return dt.replace(year=dt.year - DATE_SHIFT).strftime('%d.%m.%Y')
```

## Документы vs Регистр бухгалтерии

| Источник | Таблица | Фильтр | Сумма |
|---|---|---|---|
| **Документы** | `_DocumentXXX` | `_Posted = 1 AND _Marked = 0` | поле суммы документа |
| **Регистр бухгалтерии** | `_AccRg1112` | `_Active = 1` | `_Fld1116` |

- **Документы** — когда нужны номер, дата, назначение, контрагент
- **Регистр бухгалтерии** — когда нужны проводки Дебет/Кредит по конкретному счёту

## Фильтрация по счёту — ВАЖНО

**Никогда не фильтруй по `_Code` в WHERE регистра** — MSSQL не допускает подзапрос в агрегате. Сначала получи `_IDRRef` счёта, потом передавай параметром:

```python
# Шаг 1: получить IDRRef счёта
cur.execute("SELECT _IDRRef FROM _Acc36 WHERE _Code = '51'")
acc51 = cur.fetchone()[0]

# Шаг 2: использовать IDRRef в WHERE
WHERE d._AccountDtRRef = %s OR d._AccountCtRRef = %s
```

## Ключевые ошибки, которых надо избегать

1. **`_Posted` в регистре** — колонки `_Posted` нет в `_AccRg1112`, там `_Active = 1`
2. **`_Fld1117` вместо `_Fld1116`** — `_Fld1117` это валютная сумма (=0 для рублей)
3. **`_AccRgOpt1151`** — это таблица оптимизации, не источник данных
4. **Подзапрос `_Acc36` в WHERE** — MSSQL не допускает в агрегатных запросах, сначала бери `_IDRRef`
5. **Даты без сдвига** — всегда `shift_date()` перед запросом, `unshift_date()` перед выводом

## Субконто в Хозрасчетном — как найти Контрагента через KindCt/ValueCt

В регистре бухгалтерии _AccRg1112 (Хозрасчетный) НЕТ прямого поля «Контрагент». Вместо этого используются композитные информационные разрезы: `_KindDt{N}RRef` / `_ValueDt{N}_RRRef` для Дебетовой стороны и `_KindCt{N}RRef` / `_ValueCt{N}_RRRef` для Кредитной.

### Как работает субконто

1. **План счетов** (`_Acc36`, dec_id=36) — каждый счёт имеет настройки `ДебетовоеСубконто` и `КредитноеСубконто`
2. **Виды субконто хозрасчетные** (dec_id=1089, класс Chrc — характеристика) — определяет тип данных в каждом номере субконто (Организация, Контрагент, Счёт бухгалтерии и т.д.)
3. Настройки хранятся в VT-таблицах плана счетов (`_Acc36_VT*`)

### Важное замечание

При запросе к `_Acc36` НЕ использовать фильтр `deletedMark` — такой колонки нет. Рабочий пример из account51/query.py:

## Why

Пользователь просил сохранить опыт работы с регистрами бухгалтерии, чтобы не повторять ошибки (неправильные колонки, даты без сдвига, подзапросы в WHERE). Дополнительно: при создании страницы «Поступления оплаты» Дт51-Кт62 было обнаружено, что контрагент хранится через субконто, а не прямым полем.
