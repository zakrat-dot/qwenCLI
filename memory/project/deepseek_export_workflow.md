## Задача

Пользователь периодически выгружает историю чатов из DeepSeek — папка вида `deepseek_data-YYYY-MM-DD` с файлами `conversations.json` (вся история) + `user.json` (аккаунт). Задача: разбить на отдельные Markdown-файлы, по одному на диалог.

## Как делать (готовый скрипт)

```
py C:\AI_PROJECTS\QWEN_LOC\scripts\deepseek_to_md.py [путь к conversations.json или папке] [папка вывода]
```

- Без аргументов — берёт последнюю известную выгрузку (`D:\тексты для тракт\DeepSeek\deepseek_data-2026-10-21\conversations.json`), вывод в ту же папку.
- Один `.md` на диалог, нумерация `001_...`–`NNN_...` по хронологии (сортировка по `inserted_at`).
- Формат: `# Заголовок`, метаданные (ID/даты), затем блоки `## 👤 Пользователь` / `## 🤖 DeepSeek`.
- THINK / SEARCH / TOOL_* отбрасываются; прикреплённые файлы помечаются строкой `*📎 Прикреплённый файл: имя*` (контент файлов в выгрузке отсутствует — только file_id/имя/размер).
- Имена файлов санитизируются: табы/переносы строк → `_`, невалидные символы → `_`, длина ≤ 80.

## Структура conversations.json (на случай, если формат изменится)

- Массив диалогов: `id`, `title`, `inserted_at`, `updated_at`, `mapping`.
- `mapping` — дерево: `root` → цепочка `children`; у каждого узла `message.fragments`.
- Типы фрагментов: `REQUEST` (пользователь), `RESPONSE` (модель), `THINK` (рассуждения), `SEARCH`/`TOOL_SEARCH` (результаты поиска со ссылками), `FILE` (метаданные файлов), `TOOL_OPEN`/`TOOL_FIND` (пустые маркеры).
- Markdown-разметка ответов (код, таблицы, заголовки) сохранена в `content` как текст.

**Why:** 2026-10-23 пользователь попросил сохранить процесс, чтобы повторять в будущем при новых выгрузках DeepSeek.
**How to apply:** При упоминании выгрузки DeepSeek / conversations.json — сразу запускать скрипт, не писать конвертер заново.
