## Ключевой факт: контрагент НЕ хранится прямым полем

В регистре бухгалтерии `_AccRg1112` НЕТ колонки типа `_Counterparty_RRef`. Хозрасчетный использует композитные информационные разрезы:
- **Kind колонка:** `_KindCt{N}RRef` — байтовый UUID, указывающий тип субконто (Контрагенты)
- **Value колонка:** `_ValueCt{N}_RRRef` — байтовый RRRef на запись справочника

## Результат для счёта 51/62 (подтверждено скриптом investigate_subconto_join.py, 2026-10-07)

Для Ct1 субконто: **9285 из 11052 записей** (~84%) успешно JOIN'ятся через `_ValueCt1_RRRef` с `_Reference119`. Это подтверждает что Ct1 = Контрагенты.
- `_ValueCt2_RRRef` — банк (МОСКОВСКИЙ ФИЛИАЛ КБ МОДУЛЬБАНК АО), 1% совпадений с _Reference119
- `_ValueCt3_RRRef` — не контрагенты, 0%

## JOIN с контрагентами для Дт51-Кт62

```sql
SELECT c._Description AS counterparty, o._Description AS org, SUM(d._Fld1116) AS total_amount
FROM _AccRg1112 d
LEFT JOIN _Reference150 o ON d._Fld1113RRef = o._IDRRef       -- организация (прямое поле!)
LEFT JOIN _Reference119 c ON d._ValueCt1_RRRef = c._IDRRef   -- контрагент (субконто Ct1!)
WHERE d._Active = 1 AND d._AccountDtRRef = {h_51} 
  AND d._AccountCtRRef IN ({h_62_list})
GROUP BY c._Description, o._Description
```

## Методология исследования (применять к любым счетам/регистрам)

**Шаг 1:** Картировать все колонки регистра — найти пары Kind+Value (`INFORMATION_SCHEMA.COLUMNS WHERE TABLE_NAME='_AccRg...'`)
**Шаг 2:** Определить целевой справочник через meta_schema.duckdb (Контрагенты = _Reference119, dec_id=119)  
**Шаг 3:** Для каждой колонки Value{N}_RRRef выполнить тест JOIN с `_Reference119` — какая даёт совпадения?
**Шаг 4:** Подтвердить примерами: `SELECT TOP 5 c._Description FROM _AccRg... d INNER JOIN _Reference119 c ON d.{col} = c._IDRRef`

## Why: В 1С Хозрасчетном каждый счёт имеет назначенные ДебетовоеСубконто и КредитноеСубконто. Для Дт51 кредитная сторона (Кт) использует Ct1=Контрагент, Ct2=Банк, Ct3=Договор/Валюта.

## How to apply: При любом JOIN _AccRg1112 с контрагентами использовать `_ValueCt1_RRRef = _Reference119._IDRRef`. Для других счетов (не 51) проверять аналогично — субконто может отличаться по номеру. Если нужно найти поле в другом регистре → повторить методологию выше.
